# Требования — «Задачник для человека с истощением»

Статус: черновик v1 (сессия 1). Отмечено ✅ — решено, ❓ — открытый вопрос.

## 1. Цель и пользователи
- ✅ Личный задачник для человека с упадком сил (истощением). Главный принцип: **минимум усилий** на ввод и планирование.
- ✅ Основной пользователь — автор; задел на использование другими людьми.
- ✅ Основной сценарий: ввёл свободным текстом «хочу научиться готовить» → система сама сжимает до категории («готовка») и раскладывает по пирамиде приоритетов → пользователь сразу видит, чем заняться.

## 2. Платформа и данные
- ✅ Работает на ПК и Android-телефоне.
- ✅ ПК: **Electron-приложение** (та же JS-кодовая база, собирается в .exe с установочным пакетом — закрывает «настольный планировщик» и «создание установочного пакета» из задания). Телефон: PWA (установка из браузера).
- ✅ Данные хранятся **локально на каждом устройстве, отдельно и без синхронизации** (IndexedDB в браузере/Electron).
- ✅ Всё бесплатно или почти бесплатно.
- ✅ Напоминания — обязательная функция (по теме задания): Notifications API + собственный планировщик напоминаний.

## 3. Технологии (рекомендация, финально закрепить на следующей сессии)
- ✅ Язык: **JavaScript** (у автора нет опыта — выбираем самый простой вход; параллельно учимся в процессе).
- Сборка/инструменты: Vite + npm (закрывает «пакетный менеджер» и «СКВ» из задании).
- Хранение: IndexedDB через библиотеку Dexie (закрывает «пользовательские библиотеки»).
- Тесты: Vitest для алгоритмов (закрывает «unit-тестирование»).
- ❓ Фреймворк интерфейса: vanilla JS или лёгкий (Vue/Svelte) — решить, когда начнём UI.

## 4. Обработка ввода («ИИ») — гибрид
- ✅ Гибрид: сначала дешёвая локальная обработка (регулярки + словарь ключевых слов по категориям), незнакомые формулировки уходят во **внешний LLM API** (бесплатный тариф: OpenRouter free models / Google Gemini).
- Ввод → нормализованная категория + параметры задачи.
- Если API недоступен/не оплачен — приложение продолжает работать на правилах (деградация, а не отказ).

## 5. Приоритизация
- ✅ Этап 1 (MVP): **пирамида категорий** — уровни вида «быт/выживание → здоровье → развитие/хотелки»; задача при создании получает категорию и уровень. Пользователь выбирает уровень, которым готов заниматься.
- ✅ Этап 2 (после работающего MVP): добавить **уровень энергии** — при заходе пользователь отмечает состояние («выжат» / «норм» / «есть силы»), система показывает только посильное. Задачи получают оценку энергозатрат.
- ❓ Точный набор уровней пирамиды и категорий — спроектировать отдельно (диаграмма/таблица).

## 6. Разделение с Полиной
- ✅ Условность для учебного плана: два блока одной работы. Её тема — «Интерактивный UI с контролем состояний», моя — «Алгоритмы обработки данных и интеграция API». **По факту всю реализацию делает автор.**
