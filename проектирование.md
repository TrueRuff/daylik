# Проектирование — черновик v2 (сессия 1)

Переработано после разбора авторской системы из Obsidian (группы Необходимо / Желательно / Полезно + сферы с кратким и полным описанием).

## 1. Ядро: сферы жизни вместо пирамиды

**Сфера** = направление жизни (как «Английский язык», «Сон и Циркадные ритмы», «Питание»). Сфера живёт в одной из трёх групп:

| Группа | Расшифровка | Смысл |
|--------|-------------|-------|
| **Н** | Необходимо | Опора: без этого падает всё (сон, питание, гигиена, тренировки, учёба) |
| **Ж** | Желательно | Амбиции и хотелки (бренд одежды, скетчинг, публичные выступления) |
| **П** | Полезно | Хорошо бы, без срочности (китайский, книга, психология) |

У каждой сферы два текста (как в Obsidian, только удобно):
- **brief** — краткое: суть направления, автор перечитывает его в ежедневном экране;
- **details** — полное: методы, способы, рутина — открывается по клику.

Из сферы вырастают **практики** — регулярные дела с расписанием (например, «Сон: 23:00–07:00 ежедневно», «Тренировки: пн/ср/пт») и **разовые дела**.

## 2. Модель данных

```
Sphere {
  id, name, group: 'Н'|'Ж'|'П',
  brief, details,
  createdAt
}

Дело (Task) {
  id,
  sphereId?      — связь со сферой (может не быть)
  rawText        — что ввёл пользователь
  title          — нормализованное название
  group          — 'Н'|'Ж'|'П' (из сферы или назначено ИИ/вручную)
  durationMin    — сколько времени занимает (для подбора в окна)
  status         — 'inbox'|'todo'|'doing'|'done'|'postponed'
  dueAt, repeatRule, notes, createdAt
  source         — 'rules'|'llm'|'manual'
}
```

Решение автора: **оценки «энергозатрат» у дел нет** — выбор дела определяется желанием в моменте, а не уровнем сил. Подбор в окна идёт по длительности и приоритету группы.

DayPlan (план дня) {
  date,
  blocks: [ { id, start, end,
              kind: 'routine' | 'task' | 'free',
              label?, taskId? } ]
}
```

## 3. Календарь дня и подбор дел

- День — таймлайн 00:00–24:00.
- Сначала автоматически заполняются **routine-блоки** из практик сфер (сон, еда, пары, тренировки).
- Оставшиеся промежутки — **свободные окна**. Приложение предлагает в них дела, фильтруя: длительность дела ≤ окна, группа по приоритету (Н сначала).
- Пользователь кладёт дело в окно (блок становится `task`); не поместившееся остаётся `postponed` — наглядно видно, что уедет на потом.
- ИИ предлагает группу для новой сущности — **пользователь подтверждает одним кликом**; позже добавится перетаскивание задач между группами (Н↔Ж↔П) вручную, drag&drop.

Подбор дела в окно — ключевая алгоритмическая часть темы (фильтрация + сортировка + упаковка по времени).

## 4. Обработка ввода («ИИ», гибрид)

Ввод пользователя ИИ сначала **классифицирует по типу**, потом нормализует:

- «хочу научиться готовить» → предложение: **создать сферу** «Готовка» (группа Ж/П — уточнить у пользователя) с пустым brief;
- «помыть пол» → **разовое дело**, группа Н, ~30 мин;
- «читать 20 страниц в день» → **практика с повтором**, привязка к существующей сфере («Книга») или новой.

Внутри: правила (словарь + регулярки) → при низкой уверенности внешний LLM API (бесплатный тариф) → один и тот же формат ответа.

```
categorize(rawText) → {
  kind: 'sphere' | 'task' | 'routine',
  title, group: 'Н'|'Ж'|'П', durationMin?, repeatRule?,
  linkedSphereId?,
  confidence: 0..1, provider: 'rules'|'llm'
}
saveSphere(s) / saveTask(t) / remind(t, when) / buildDay(date) → DayPlan
```

## 5. Экраны (минимум для MVP)

1. **Ежедневный (главный)**: таймлайн этого дня — расписание из рутин и поставленных дел, свободные окна с предложениями, что влезет.
2. **Сферы**: дерево Н/Ж/П как в Obsidian; клик — brief (краткое), полный текст (details), практики и дела сферы.
3. **Ввод**: одна строка → ИИ-разбор (сфера / дело / практика + группа) → подтверждение кликом → куда легло.
